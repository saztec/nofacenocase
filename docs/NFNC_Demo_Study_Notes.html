1. The 30-second pitch

NoFaceNoCase is a website for hospital staff that helps them keep an eye on patients who might be in distress or at risk of falling.

A nurse takes or uploads a photo of a patient during a check-in. The website uses artificial intelligence to read the patient’s facial expression, read the mood of the nurse’s written note, and check whether the patient is actually in their bed. If something looks wrong, it automatically emails the doctor.

Everything runs on Amazon Web Services (AWS) — Amazon’s cloud computing platform.

Say this: “NoFaceNoCase is a serverless patient-monitoring website built entirely on AWS. It uses image recognition to spot at-risk patients earlier than manual checks can.”

2. The problem, in plain words

Hospital wards don’t have enough staff to watch every patient all the time. The patients who most need watching — confused, distressed, or likely to wander and fall — are exactly the ones who can quietly get worse between a nurse’s rounds.

Two warning signs are easy for a busy nurse to miss:

  • How the patient feels — fear or sadness they don’t say out loud.
  • Getting out of bed at night — a big cause of falls and wandering.

NoFaceNoCase gives staff an objective “second pair of eyes” for both.

3. How it all fits together

Think of a restaurant: you (the customer) never go into the kitchen. You talk to a waiter, who takes your order to the kitchen, and the kitchen uses the fridge, the chefs, and the suppliers to make your meal.

The website works the same way:

  • You / the nurse = the customer, using the web page.
  • API Gateway = the waiter who takes requests.
  • Lambda = the kitchen that does the actual work.
  • DynamoDB, S3, Rekognition, Comprehend, SNS = the fridge, chefs and suppliers the kitchen uses.

The nurse never touches those services directly — the “waiter and kitchen” handle it all behind the scenes.

4. Every AWS service, explained simply

Tap each one. Each has: what it is, an everyday analogy, how your app uses it, and a one-line answer if you’re asked.

Amazon S3 — storage
Analogy: a giant, unlimited filing cabinet in the cloud.

What it is: a place to store files — images, and the website’s own pages.

How you use it: two “drawers” (called buckets). One holds your website files; the other holds the patient photos, locked so the public can’t see them and set to auto-delete after 30 days.

If asked: “S3 stores my website and the patient photos. The photo bucket is encrypted and blocked from public access.”
AWS Lambda — the worker
Analogy: a worker who only clocks in when there’s a job, does it, and clocks out — you only pay for the seconds they work.

What it is: code that runs on demand without you managing a server (“serverless”).

How you use it: one Lambda function is the “brain” that handles every action — saving a patient, running a photo through AI, sending an alert.

If asked: “All my logic lives in one Lambda function. It talks to every other AWS service using code.”
Amazon API Gateway — the front door
Analogy: the receptionist who checks your pass before letting your request through to the office.

What it is: the secure doorway between the website and the Lambda.

How you use it: the web page sends requests here; it checks the user is logged in, then passes them to Lambda.

If asked: “API Gateway is the secure entry point to my backend, and it checks the login token on every request.”
Amazon DynamoDB — the database
Analogy: a super-fast digital spreadsheet that never slows down.

What it is: where all the data is stored — patients, check-ins, medications.

How you use it: three tables. Your app can Create, Read, Update and Delete records (that’s “CRUD” — see jargon buster).

If asked: “Patient data lives in DynamoDB. I have full CRUD — I can add, view, edit and delete patients.”
AWS Rekognition — the image AI (⭐ two parts)
Analogy: a pair of trained eyes that can describe what’s in a photo.

What it is: Amazon’s image-recognition service. You use it in two ways:

1. DetectFaces (ready-made): Amazon already trained this. You hand it a face photo and it reports the emotion — happy, sad, fearful, etc.

2. Custom Labels (you trained this yourself): Amazon can’t tell if a hospital bed is occupied, so you trained your own model to do it. This is the impressive bit — see section 5.

If asked: “I use Rekognition two ways — a ready-made model for facial emotion, and a model I trained myself for bed occupancy.”
Amazon Comprehend — the text AI
Analogy: a reader who can tell if a sentence sounds positive, negative or neutral.

What it is: Amazon’s language service. It reads text and reports the sentiment (the mood).

How you use it: when a nurse types a note, Comprehend reads it and labels it Positive / Negative / Neutral / Mixed — a second signal alongside the face.

If asked: “Comprehend reads the clinical note and tells me its sentiment, complementing the facial emotion.”
Amazon Cognito — the login system
Analogy: the security guard who checks staff ID badges and knows who’s allowed where.

What it is: handles user accounts and logins.

How you use it: only logged-in staff can use the site. Staff are put into groups — nurse or clinician — and only clinicians are allowed to delete patient records.

If asked: “Cognito handles login, and its groups give me role-based access — only clinicians can delete records.”
Amazon SNS — the alert sender
Analogy: an automatic pager that texts the doctor when something’s wrong.

What it is: a notification service that sends messages (here, emails).

How you use it: when a patient looks very distressed, or keeps leaving their bed, SNS emails the assigned doctor automatically.

If asked: “SNS sends the distress and wandering alerts by email to the clinician.”
Amazon CloudFront — the fast, secure delivery
Analogy: local pickup points so everyone gets the website quickly — and it arrives sealed (secure).

What it is: delivers your website fast and over HTTPS (the secure, padlock version of a web address).

How you use it: it sits in front of your S3 website so the site loads over a secure https:// link — the URL you demo with.

If asked: “CloudFront serves my site over HTTPS with a security certificate — that’s my live demo link.”
AWS IAM — the permissions rulebook
Analogy: a keycard that only opens the exact doors you need — nothing more.

What it is: controls what each part of your system is allowed to touch.

How you use it: your Lambda is given only the permissions it needs, pointed at the exact resources (not “everything”). This is called least privilege and it’s good security.

If asked: “I used a least-privilege IAM role — the Lambda can only touch the specific resources it needs, no wildcards.”

5. The star of the show: your own trained model

This is the part to be proud of, because you built and trained it yourself — not something Amazon handed you ready-made.

What you did, step by step

  • You collected about 35 photos — some of beds with a person in them, some of empty beds.
  • On the “occupied” photos you drew a box around the person (called a “bounding box”) and labelled it occupant.
  • You left the empty-bed photos unlabelled — that teaches the model what “nobody here” looks like.
  • AWS trained the model and gave you a score card. Then it can look at a new photo and say “occupied” or “empty”, and draw a box where it sees a person.

The problem you solved (great story to tell)

At first, a messy but empty bed got mistaken for “occupied” — the crumpled sheets looked like a body. You tried adding more messy-empty photos, but it still slipped through. So you looked at the confidence scores: a real person scored about 21%, the false alarm about 13.6%. You set the cut-off (called MinConfidence) to 17 — right between them. That fixed the false alarm while still catching real patients.

Say this: “I trained a Custom Labels model on my own photos to detect bed occupancy. When a messy empty bed caused a false positive, I diagnosed it using the confidence scores and tuned the threshold to fix it — a real development and problem-solving process.”

6. Numbers to remember

0.78F1 score (overall accuracy grade of your model)
1.00Recall — it never missed a real occupied bed

“F1” is just a single grade from 0 to 1 that balances two things: how often the model is right when it says “occupied”, and how often it catches real occupied beds. Higher is better.

6b. Jargon buster

What does “serverless” mean?

You didn’t rent or manage a computer that runs 24/7. Your code (Lambda) only runs when needed, and AWS handles the machines. Cheaper and less maintenance.

What is an “API”?

A way for two pieces of software to talk. Your web page sends a request to the API, and the backend sends an answer back — like ordering through a menu.

What is “CRUD”?

The four things you can do with data: Create (add), Read (view), Update (edit), Delete (remove). Your app does all four on patients.

What is “HTTPS” / the padlock?

The secure version of a web address. Data is encrypted between the browser and the site so no one can snoop. CloudFront gives you this.

What is a “JWT” / login token?

A digital wristband you get after logging in. Your browser shows it on every request to prove who you are. Cognito issues it; API Gateway checks it.

What is a “bounding box”?

The rectangle drawn around an object the AI found in a photo — here, around the person in the bed. Your model returns its exact position.

What is “least privilege”?

A security idea: give each part only the exact access it needs, nothing extra. Limits the damage if something is ever misused.

7. Questions they might ask (with answers)

“Why did you use DynamoDB instead of a normal database?”

“It’s fast, fully managed, and fits a serverless app well — no database server to run. The spec allowed either RDS-MySQL or DynamoDB, and DynamoDB matched my architecture.”

“How is the facial emotion different from your bed model?”

“Facial emotion uses DetectFaces — a model Amazon already trained. The bed model is Custom Labels — I trained it myself on my own photos, for a task Amazon’s service doesn’t cover.”

“How did you keep patient data secure?”

“HTTPS everywhere via CloudFront, login through Cognito with nurse/clinician roles, a least-privilege IAM role, and the photo bucket is encrypted with public access blocked and 30-day auto-delete.”

“What was the hardest part?”

“Getting my custom model reliable. A messy empty bed caused a false positive. I used the confidence scores to set the right threshold, which fixed it without losing real detections.”

“Is the AI result real or hardcoded?”

“Fully live. The emotion, sentiment and bed result all come back from real AWS API calls each time — you can see the confidence numbers change per photo.”

“What would you improve?”

“A bigger, more varied photo set to raise the model’s precision, a second ‘bed’ label to check the camera is aimed right, and continuous monitoring instead of on-demand checks.”

8. Demo-day checklist

Before you present:

  • Start the Rekognition Custom Labels model — the bed check won’t work unless it says RUNNING.
  • Log in once to check everything loads.
  • Have two bed photos ready (one occupied, one empty) and a face photo.
  • Open your AWS console tabs in advance so there’s no waiting.

After you present: STOP the model so it doesn’t keep charging.

One-line summary to close with:

“NoFaceNoCase is a secure, serverless AWS app that uses two kinds of image recognition — a ready-made one and one I trained myself — plus Comprehend, Cognito, SNS and CloudFront, each doing a real job in a hospital workflow.”
